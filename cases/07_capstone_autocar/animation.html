Cost vs accuracy vs forgetting — assemble the hybrid memory system that beats every pure approach.

1 · The hybrid architecture — toggle each path and see what breaks

👁 Seeing Live data flows left→right. Every raw experience lands in the vector DB. From there, two paths feed the car: retrieval (instant, every drive) and periodic replay that consolidates patterns into the LoRA weights.
🎮 Try Untick retrieval: the car loses instant recall of rare/new events. Untick replay: nothing ever gets compressed into weights — the car depends entirely on the DB being online. The status line tells you the cost of each choice.
📖 Why a hybrid beats pure replay or pure retrieval

The three layers

  • Foundation model — frozen general knowledge (language, physics, road rules).
  • Stable LoRA — core driving skills, updated by periodic replay (monthly/quarterly). Fast at inference.
  • Experience memory — vector DB of raw episodes, updated in real time, retrieved for rare/novel situations.

Why not just retrieval?

No generalization, and if the DB is down the knowledge is gone. You also can't fit 100M experiences into a context window.

Why not just replay?

Retraining is expensive and slow; you don't want to re-certify a safety-critical model every day.

The balance (hippocampus → cortex)

Retrieval handles day-to-day surprises (construction, local quirks). Replay consolidates recurring patterns into weights quarterly — exactly how the brain moves episodic memories into long-term cortical storage.

3 · The memory funnel — 100M experiences → 3 lessons

👁 Seeing A query falls through the hierarchy: vector search narrows 100M memories to ~100, a reranker to ~10, a summarizer to ~3 lessons that fit the context window. The number shrinks at each stage.
🎮 Try Press Run and follow one query down. Notice the model never sees the full memory — only the 3 distilled lessons reach it. That's how retrieval scales past the context limit.
📖 Why a hierarchy instead of one big search?

The scaling problem

You can't put 100 million experiences in a 32k-token context. So retrieval is staged, like computer memory (disk → SSD → RAM → cache):

100M → vector search → 100 → rerank → 10 → summarize → 3 → context

Progressive abstraction

A mature system doesn't store raw events forever. Thousands of "saw snow on road X" episodes get compressed into one rule: "when road temp < 0°C, trust lane markings less." Raw events → episode summaries → concepts → rules.

Where replay and retrieval converge

That compression is consolidation — the slow replay path in Panel 1. The funnel feeds inference today; consolidation bakes the recurring lessons into weights for tomorrow.

📖 How to balance the three axes in production

The three axes

  • Cost — GPU hours for retraining + storage for the memory. Retrieval is cheap to update; replay is expensive.
  • Accuracy — average performance across every task/situation seen so far.
  • Forgetting — how much old-task skill dropped. Retrieval ≈ zero; naive ≈ a lot.

What the sliders model

  • Replay frequency — rare → cheap but weights lag; frequent → accurate but costly. Automotive often picks quarterly/monthly.
  • Memory size — how many raw experiences you keep for retrieval. More = better rare-event recall, higher storage.

Why the hybrid wins

Retrieval gives immediate, no-forgetting access to specifics; periodic replay compresses recurring patterns into fast, dependency-free weights. Together they dominate any single approach — the result this capstone proves.

Your capstone question, answered

"How do I keep fine-tuning a self-driving model as new data arrives — cheaply, accurately, without forgetting?" → Retrieval for the daily stream, periodic replay-based LoRA for consolidation, frozen base for stable core skills. Tune frequency and memory to your budget. Don't choose one tool; compose them.
