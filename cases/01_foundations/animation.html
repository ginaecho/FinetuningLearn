📖 What is this really? (loss, gradient, learning rate)

What is "the model" here?

A model is just a bunch of numbers called weights (or parameters). To "train" it means to find weight values that make its predictions correct. In this panel we pretend there's a single weight — the ball's horizontal position x.

What is the curve (the loss landscape)?

The loss measures how wrong the model is — higher = more wrong. For every possible weight value, there's a loss. Plotting loss vs. weight gives this curve, the loss landscape. Training = finding the lowest point (smallest loss = best model).

What is the orange arrow (the gradient)?

The gradient is the slope of the curve under the ball — it points in the direction loss increases. So to reduce loss we step the opposite way (downhill). That's literally the update rule, called gradient descent:

new_weight = old_weight − learning_rate × gradient

What does the Learning rate slider do, and why?

  • Small LR → each step is a baby step. Safe, never overshoots, but slow (many steps).
  • Large LR → each step is a big jump. Fast at first, but it can leap past the bottom and bounce back and forth, or even climb out — unstable.

Why it matters for fine-tuning: a pre-trained model is already near a good point. A big LR would knock it far away and destroy what it knew. So fine-tuning deliberately uses a small LR to nudge gently. (Try it: set LR high and watch the ball bounce instead of settle.)

What does ▶ Train show?

It repeatedly applies the update rule (one step every frame) so you see the ball roll downhill. The "step" counter is how many updates have happened; "loss" is the current height. Real training is exactly this, just with millions of weights instead of one.

2 · Pre-train vs Fine-tune — same hill, different start

Pre-train: start from random weights, take many big steps to a good minimum (expensive, done once).
New task: the landscape shifts a little — the old minimum isn't perfect anymore.
Fine-tune: start from the already-good weights and take a few small steps to the new minimum. Cheap, fast — the whole point.

📖 What do the 3 buttons mean, and what happens when I click?

This panel tells a story in three clicks. Same downhill idea as Panel 1, but now it shows the difference between pre-training and fine-tuning. The curve is again the loss landscape; the ball is the model's weights.

① Pre-train (from scratch) — what is "pre-training"?

Pre-training = teaching a model from random weights on a big, general task until it's good. It's done once, it's expensive (lots of data + compute), and it's what companies do to create base models like Llama.

When you click ①: the ball starts at a random spot (orange) and takes many big steps downhill until it reaches the bottom (a good model). You're watching a model learn a task from nothing. That bottom point = the "pre-trained weights."

② New task arrives ↘ — what changes?

The real world shifts: new data, a new city, a new sensor, a new instruction style. We model that by moving the whole landscape sideways. Now the old bottom (where the ball sits) is no longer the lowest point — the model is slightly wrong for the new task.

When you click ②: the curve shifts and a small marker shows the new minimum. The ball doesn't move yet — it's still at the old solution, which is now a bit off. This is the moment a fine-tuning job begins.

③ Fine-tune — what is "fine-tuning"?

Fine-tuning = continue training the already-good model on the new task, using a small learning rate for a few steps. You're not starting over — you're adapting.

When you click ③: the ball (now green) takes a few small steps from the old solution to the new minimum. Notice it gets there in far fewer steps than pre-training (①) needed. That speed/cost saving is the entire reason fine-tuning exists.

So what was "trained"? What does clicking show?

  • ① trains a model from scratch → expensive, many steps.
  • ② doesn't train — it just shows the task changing under the model.
  • ③ trains the same weights a little more → cheap, few steps, reaches the new best.

The hidden danger (Case 05): after ③ adapts to the new task, is the model still good at the old task (the original bottom)? Often not — moving to the new minimum can make it worse at the old one. That's catastrophic forgetting, the core problem of your self-driving capstone.

3 · Full fine-tuning vs LoRA — how many weights actually move?

Each square is a weight. Orange = updated this step. Full fine-tuning updates every weight (lots of memory + compute). LoRA freezes the grid and learns a tiny side-path instead → that's the peft magic you'll implement in Case 02.
📖 What are these squares, and what do the buttons show?

What is the grid?

Each little square is one weight of a model (a model has from thousands to billions of them, usually organized as matrices). Color = whether that weight was changed in the latest training step: orange = updated, dark = left alone.

Full fine-tune — what does it show?

Almost every square flickers orange: full fine-tuning lets the optimizer change all the weights. Most accurate in principle, but you must store gradients + optimizer state for every weight → huge memory, and you save a whole new copy of the model per task.

LoRA — what does it show?

Only a thin strip stays orange: LoRA freezes the big grid (no orange there) and trains a tiny add-on instead — here drawn as the strip, only ~4% of the weights. Far less memory, and the adapter is so small you can keep one per task.

Why does that matter?

  • Cost/efficiency: training 4% instead of 100% is what lets a 7B model fine-tune on one GPU.
  • Forgetting: the frozen grid keeps the original knowledge intact — you can't overwrite what you never change. (More in Case 06.)
