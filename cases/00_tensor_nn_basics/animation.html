1 · unsqueeze: why shape (5,) breaks, but (5, 1) works

📖 Why does nn.Linear(1, 64) need the last dimension to be 1?

The rule

nn.Linear(in_features, out_features) reads the last dimension of whatever you feed it. That last dimension must equal in_features.

  • nn.Linear(1, 64) → last dim must be 1
  • nn.Linear(5, 64) → last dim must be 5
  • nn.Linear(768, 64) → last dim must be 768

Everything before the last dimension is treated as "batch" — independent samples processed in parallel.

Why? Because of how matrix multiplication works

nn.Linear does y = x @ W.T + b where W has shape (out, in). For the @ to work, x's last dim must equal W's last dim = in.

The unsqueeze problem, concretely

You generated 5 numbers: x = torch.tensor([2.5, -0.8, 1.3, 0.4, -1.9]). Shape is (5,).

But what does (5,) mean? PyTorch can't tell:

  • Is it 5 samples, each with 1 feature? → shape should be (5, 1)
  • Is it 1 sample with 5 features? → shape should be (1, 5)

You have to tell PyTorch which you mean. That's what unsqueeze does.

unsqueeze(0) vs unsqueeze(1) vs unsqueeze(-1)

The number tells PyTorch where to insert the new size-1 dimension:

  • unsqueeze(0): insert at position 0 (the front). (5,) → (1, 5). Meaning: "wrap all 5 as 1 group." Now it's 1 sample with 5 features.
  • unsqueeze(1) or unsqueeze(-1): insert at position 1 (the end). (5,) → (5, 1). Meaning: "each number is its own group." Now it's 5 samples, each with 1 feature.

-1 means "the last position" — same as 1 when you start with a 1D tensor. People write -1 because it works regardless of how many dimensions there already are.

squeeze() — the undo button

squeeze() removes all dimensions of size 1, returning to the simpler shape. (5, 1) → (5,) and (1, 5) → (5,).

Visual cheat sheet

(5,) = 5 numbers, no grouping
(5, 1) = 5 rows, 1 column = 5 samples × 1 feature
(1, 5) = 1 row, 5 columns = 1 sample × 5 features

2 · The matrix algebra behind nn.Linear — dimensions must line up

3 2 4
nn.Linear(k, n) computes y = x @ Wᵀ + b. The inputs are matrices: x is (m, k), the weight Wᵀ is (k, n). For the multiply to work, x's last dim (k) must equal Wᵀ's first dim (k) — the two inner numbers. The result y is (m, n) — the two outer numbers. Hit Break the shape to see the mismatch error.
📖 The matrix-multiply rule, step by step

The shape rule (memorize this one line)

(m, k) @ (k, n) = (m, n)

To multiply two matrices, the inner dimensions must match (both k here). They "cancel," leaving the outer dimensions (m and n) as the result's shape.

  • (3, 2) @ (2, 4) = (3, 4) ✓ — inner 2 = 2
  • (3, 2) @ (3, 4) ✗ — inner 2 ≠ 3, RuntimeError

How one output cell is computed (the dot product)

Each cell of the result is a dot product: take row i of the left matrix and column j of the right matrix, multiply element-by-element, and add them up.

y[i,j] = Σ x[i,:] · Wᵀ[:,j]

That's why the inner dims must match — the row and the column need the same length to pair up. Watch the animation: the cyan row and purple column light up, and their products sum into one green cell.

Mapping to nn.Linear(1, 64)

Your data x after unsqueeze(1) is (batch, 1) — so k = 1. The layer's weight W is (64, 1), and Wᵀ is (1, 64) — so k = 1, n = 64.

(batch, 1) @ (1, 64) = (batch, 64) ✓

If you forgot the unsqueeze and x was (batch,) with no second dimension, there's no "last dim = 1" to line up against Wᵀ's first dim — that's the crash you saw in Panel 1.

What is "+ b" (the bias)?

After the multiply, a bias vector of shape (n,) is added to every row. It shifts each output. It's broadcast across all m rows — same bias for every sample.

Why "echelon" / dimensions matter for you

Reading shapes as (m, k) @ (k, n) = (m, n) is the fastest way to debug any model. When an LLM agent writes code and you get a shape error, you scan for the two inner numbers that don't match — that's 90% of deep-learning debugging.

3 · Inside nn.Sequential: layers and activations

📖 What do Linear, Tanh, and Sequential mean?

What is nn.Linear(in, out)?

A linear layer computes y = Wx + b where W is a weight matrix of shape (out, in) and b is a bias vector of shape (out,). It takes an input with in features and produces an output with out features.

Example: nn.Linear(1, 64) takes 1 number in, produces 64 numbers out. That 64-wide vector is a richer representation the next layer can work with.

What is an activation function (Tanh)?

Tanh squishes any value to the range [-1, 1]. It's a non-linear function — this is critical because without it, stacking linear layers would collapse to a single linear layer (matrix multiply is associative). The non-linearity lets the network learn curves, not just lines.

Other activations: ReLU (max(0, x) — zeroes negatives), GELU (smooth ReLU, used in transformers), Sigmoid (squishes to [0, 1]).

What is nn.Sequential?

nn.Sequential chains layers in order. Data flows through them one by one: x → Linear → Tanh → Linear → Tanh → Linear → y. It's the simplest way to build a network. For fancier architectures (skip connections, branching), you subclass nn.Module instead.

Shape through the network

If input is (batch, 1):

  • Linear(1, 64) → (batch, 64)
  • Tanh → (batch, 64) (same shape, values squished)
  • Linear(64, 64) → (batch, 64)
  • Tanh → (batch, 64)
  • Linear(64, 1) → (batch, 1)

The shape at each stage is the single most useful debugging tool. Print it when confused.

📖 What happens in each step of training?

The four steps (every training loop ever)

  • 1. Forward pass — run input through the network to get a prediction. pred = model(x)
  • 2. Compute loss — measure how wrong the prediction is. loss = MSE(pred, target). MSE = mean of (pred - target)^2.
  • 3. Backward pass — compute gradients: how much each weight contributed to the error. loss.backward(). PyTorch does this automatically.
  • 4. Optimizer step — update each weight in the direction that reduces loss. optimizer.step(). How big a step? That's the learning rate.

Before each cycle: optimizer.zero_grad() clears old gradients (they'd accumulate otherwise).

What is the optimizer (Adam)?

Adam is the default optimizer. It keeps running averages of gradients and their squares (momentum + adaptive learning rate). You rarely need to change it. torch.optim.Adam(model.parameters(), lr=1e-3) — the lr is the learning rate, the most important hyperparameter.

What does the Learning rate slider show?

  • Too high (0.1): weights overshoot — loss jumps around or explodes.
  • Too low (1e-5): weights barely move — loss crawls, takes forever.
  • Just right (~1e-3): smooth, steady decrease.

For fine-tuning (Cases 01+), the learning rate is lower (1e-4 to 2e-4) because you don't want to move far from the pretrained weights.

How this connects to everything else

Every technique in this curriculum — fine-tuning, LoRA, QLoRA — uses this same loop. The only things that change: which parameters get updated (LoRA: just the adapters), what precision they're stored in (QLoRA: 4-bit base), and how the data is formatted (SFT: instruction-response pairs).
