Case 06 · Continual Learning Toolkit

Four ways to stop forgetting: replay, regularization, and modular adapters.

1 · Replay buffer — mix old data into new training

15%
Each square is one training sample in a mini-batch. Green = new Task-B data. Gray = replayed Task-A data. Even a small replay ratio keeps the optimizer anchored to old knowledge.
📖 How does replay prevent forgetting?

The idea

Instead of training only on new data, you mix in a small fraction of representative old samples. The optimizer must find parameters that work for both distributions simultaneously.

What does the slider show?

  • 0% replay = pure new-task training → maximum forgetting.
  • 15–30% replay = strong protection with little slowdown (the sweet spot in most papers).
  • 50%+ replay = very safe but you learn the new task slower (old data dominates).

Why it works

The loss landscape for Task A and Task B usually overlap. By showing both tasks, the optimizer settles in a shared valley instead of jumping from one basin to another.

Production note

Replay remains the strongest baseline in continual learning research. Many fancy methods lose to a well-designed replay buffer (see tutorial §2 and §9).

2 · EWC — protect important weights with a penalty

1000
A single weight's journey: old optimum at 0.4, new training pulls it toward 0.9. With EWC (toggle), a spring pulls back proportional to how important this weight was for Task A.
📖 What is EWC and the Fisher information?

Elastic Weight Consolidation (EWC)

After training on Task A, EWC estimates which parameters matter most for A (using Fisher information). When training on B, it adds a penalty for changing those important parameters:

Loss = Loss_B + (λ/2) · Σ F_i · (θ_i − θ*_i)²

Where F_i is Fisher importance and θ*_i is the old optimal value.

What does the λ slider control?

  • λ = 0 → no penalty → pure B training → forget A.
  • λ = 1000 → strong spring → weight stays near old optimum → A protected, but B learns slower.
  • Too high λ → the model can't learn B at all (frozen).

Limitation

EWC protects A but doesn't teach B as well as replay does, because it constrains the parameter space. That's why replay usually wins.

3 · Adapter library — one LoRA per task, zero interference

Each task gets its own small adapter (green). The base model (gray) stays frozen forever. At inference, load the right adapter. No forgetting — but you need a task detector or router.
📖 How do per-task adapters eliminate forgetting?

The architecture

Instead of training one adapter on A, then overwriting it on B, you save adapter A to disk, train a fresh adapter B, save it, train C, save it. Each adapter is a tiny file (~tens of KB for small r).

Inference

Load the base model + the adapter for the task at hand. If you don't know the task, you need a router (learned or heuristic) that picks the adapter.

Trade-offs

  • Pros: Zero forgetting. Each adapter is independent. Cheap to store many.
  • Cons: Need task ID at test time. No cross-task generalization within a single adapter.
  • Scale: Thousands of adapters can be served concurrently (see MLSys 2024 paper in tutorial).

Connection to capstone

In a self-driving car, you might keep adapters for "highway", "urban", "construction zone". The common "core driving" knowledge lives in the frozen base; situation-specific corrections live in adapters.
