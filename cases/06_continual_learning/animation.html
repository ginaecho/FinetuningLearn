📖 How each method works

Naive (no protection)

Train only on Task B data. All weights shift toward B. Task A is destroyed. This is the catastrophic forgetting baseline from Case 05.

Replay 🔄

Experience replay mixes old Task A samples into every training batch. If 30% of each batch is Task A data, the model keeps practicing A while learning B. The Replay ratio slider controls this mix. Higher ratio = better A retention, but slower B learning.

EWC 🔒

Elastic Weight Consolidation adds a penalty for changing "important" weights. After training on A, we compute the Fisher information for each weight — a score of how much that weight matters for Task A. During B training, the loss becomes: L = L_B + (λ/2) · Σ F_i · (θ_i − θ*_i)². High-Fisher weights resist change. The λ slider controls penalty strength.

Adapters 🧩

Per-task adapters (like LoRA in practice) give each task its own parameters. Task A's weights are frozen forever. Task B gets a fresh set. A router picks which set to use. Forgetting is impossible — but you need storage for each adapter.

Self-driving takeaway

Real autonomous vehicles use a combination: adapters for distinct environments (highway vs. city vs. snow), replay for gradual improvements, and EWC-like regularization during fine-tuning. Case 07 shows how to combine these.

📖 Which method should I use in practice?

Replay is the strongest baseline in research — simple, effective, and doesn't require computing Fisher information. The cost: you need to store old data.

EWC is useful when you can't store old data (privacy, storage limits). It only needs the Fisher scores from the previous task, not the actual data.

Adapters guarantee zero forgetting, but you need one adapter per task. In LoRA terms, this is cheap (~1-5% of model params per adapter), so it's very popular in practice.

Production systems (like autonomous vehicles) combine all three: adapters for major environment shifts, replay for continuous improvement, and regularization as a safety net. Case 07 puts it together.
