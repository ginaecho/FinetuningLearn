📖 What is ΔW, "rank", and B·A?

What is ΔW (the left heatmap)?

When you fine-tune, every weight matrix W changes by some amount. That change is itself a matrix, ΔW ("delta-W" = how much the weights moved). The left heatmap is a pretend ΔW; red/blue = positive/negative change.

What is "rank"?

Rank = how many independent directions a matrix really uses. A low-rank matrix looks complex but is secretly built from a few patterns repeated/scaled. Key empirical fact: the ΔW a task needs is nearly low-rank — it lives in just a handful of directions.

What is B·A (the right heatmap)?

Instead of storing the full ΔW, LoRA builds it from two skinny matrices: ΔW ≈ B · A, where A is r×in and B is out×r. The number r is how skinny they are.

What does the rank r slider show?

  • Small r → very few numbers to store (cheap), but the right heatmap looks blurry — it can't capture every detail. Watch the "reconstruction error" rise.
  • Bigger r → right heatmap matches the left better (error drops), but costs more params.

The win: error usually gets tiny at a small r (like 4–16), long before you pay for full rank. Compare the two param counts shown — LoRA stores a fraction.

2 · How it wires into a layer

Forward pass becomes:  y = Wx + (B·A)x · (α/r)
• W is frozen (gray) — gradients skip it.
• A, B are trained (green) — that's all the optimizer touches.
• B starts at 0 → at step 0 the model == the pretrained model (safe start).
• After training you can merge: W ← W + B·A·(α/r) → zero extra inference cost.
📖 What does the wiring show, and what is "frozen"?

What are the boxes and flowing dots?

This is the forward pass — how an input x becomes an output y. The dots are data flowing. There are two paths that get added together: y = Wx + (B·A)x·(α/r).

  • Top path (gray, W): the original pre-trained layer.
  • Bottom path (green, A then B): the small LoRA adapter.

What does "frozen" mean?

Frozen = we tell the optimizer "never change these numbers." During training, gradients flow but W is held fixed; only A and B are updated. That's why only ~0.4% of params are "trainable" even though the model is huge.

Why start with B = 0?

If B is all zeros, then B·A = 0, so at step 0 the adapter adds nothing and the model behaves exactly like the pre-trained one. Training then gently grows the adapter from there — a safe start with no sudden jump in behavior.

What is α (alpha) / the scale?

α/r is a volume knob on the adapter's effect. Bigger α = stronger update. Dividing by r keeps the strength stable when you change r, so you can tune r and α somewhat independently.

What is "merge"?

After training you can compute W ← W + B·A·(α/r) once and fold the adapter back into W. Now it's an ordinary layer again — same speed as the original, no extra cost at inference time. You can also keep them separate and swap different adapters per task.

3 · Why this matters at LLM scale

1024 8
A single 4096×4096 attention matrix = 16.7M params. With r=8, LoRA needs 2·4096·8 ≈ 65K — about 0.4%. Multiply across all layers → that's how a 7B model fine-tunes on one GPU.
📖 What do the sliders prove?

This panel does the arithmetic at real LLM sizes so the savings feel concrete.

The two sliders

  • matrix size d — a weight matrix is d×d, so full fine-tuning trains d² numbers. At d=4096 that's ~16.7 million for one matrix.
  • rank r — LoRA trains only 2·d·r numbers instead.

What the green bar shows

The trainable fraction 2·d·r / d² = 2r/d. As models get bigger (larger d), this fraction shrinks — LoRA gets relatively cheaper the larger the model. That's the punchline: the bigger the model, the more LoRA saves you.

Why you care (your capstone)

Cheap-to-train adapters are the "cost & efficiency" half of your self-driving question. Each new data update can be a small adapter instead of a full retrain — fast, affordable, and it leaves the base model untouched.
